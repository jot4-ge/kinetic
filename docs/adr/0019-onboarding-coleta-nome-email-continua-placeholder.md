# Onboarding passa a coletar o nome real; e-mail continua placeholder

[ADR-0014](0014-identidade-usuario-camada-1-fixa-sem-dados-reais.md) decidiu, para a Camada 1, não coletar `nome` nem `email` — nenhuma tela da v1 precisava dessa informação para funcionar, e coletar dado pessoal sem contrapartida de valor foi julgado pior do que não coletar. Esta ADR revisa parcialmente essa decisão: a v1 ganha personalização (saudação em "hoje", identidade no Perfil) que dá ao `nome` um uso real. O item (b) de ADR-0014 — "`nome` e `email` não são coletados nesta fase" — deixa de valer para `nome`; para `email` permanece integralmente válido, junto com sua justificativa original.

**O onboarding passa a coletar `nome`, obrigatório.** Validação: string não vazia após `trim`, limite de 80 caracteres. Substitui o placeholder fixo `"Você"` (`NOME_PLACEHOLDER` em `onboarding-core.ts`, agora removido) pelo valor digitado. No modo de regeneração de Plano, o campo vem pré-preenchido com o nome atual do Usuário (`formularioDeUsuario`) — a pessoa não redigita o próprio nome a cada novo Plano. O nome é usado em dois lugares: uma saudação contida no cabeçalho da tela "hoje" (`saudacaoDoDia`, variando por hora do dia — bom dia/boa tarde/boa noite — tom sem exclamação, brand §3.1) e no bloco de identidade do Perfil.

**`email` não é coletado — a decisão e a justificativa de ADR-0014(b) continuam de pé.** Segue sem uso até a Camada 2 (login/nuvem, [ADR-0017](0017-multiusuario-escopo-da-v2.md)); coletar agora seria dado sem contrapartida, exatamente o raciocínio original. O placeholder `usuario@exemplo.invalid` (RFC 2606) permanece.

**O nome fica local (IndexedDB), como todo o resto** — não sai do dispositivo, mesma garantia de privacidade da Camada 1 (ADR-0007). A Camada 2 continua sendo o momento em que identidade real (login) substitui o `id` fixo `usuario-local`; isso não muda: coletar `nome` na v1 é personalização de produto, não é o começo de multi-usuário.

**Usuários existentes com o placeholder `"Você"`** (dados salvos antes desta fase) não são migrados ativamente — não há tela ou redirecionamento forçado para preencher o nome retroativamente. O placeholder aparece onde o nome apareceria (saudação, Perfil) até a pessoa gerar um novo Plano, momento em que o formulário exige o nome real como qualquer outro campo obrigatório. Não quebra: `"Você"` é uma string válida como qualquer outra para os fins do schema e da UI.
